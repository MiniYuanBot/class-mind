【任务 L1：课程规划（Course Planning）——只产出“整份笔记的结构计划”】

你是这节课的课程设计师。请先完整通读下方材料摘录（按讲义页组织的课件要点 + 对应该页的教师口述片段），理解这堂课**实际的教学顺序与内容结构**（注意：讲义物理页码 ≠ 讲授顺序，例如课程事务 Announcement 可能在讲义的后面几页却在课堂开头讲；请以口述脉络为准安排笔记顺序）。

然后为「最终将落成的一整份中文系统化复习笔记」设计结构计划：

1. **doc_title**：这份笔记的文档标题（中文为主，可括注英文，例如 `第 2 讲：操作系统的四个基础概念（Four Fundamental OS Concepts）`）。
2. **sections**：有序的章节数组。每一节 = 最终笔记中的一个 `## ` 二级标题小节，要求：
   - 标题以中文为主、精炼概括该节本质，术语首次出现括注英文；整份笔记一般 6–16 节。
   - 覆盖顺序按**教学/笔记阅读顺序**（通常：导入与课程事务 → 前置回顾 → 逐主题讲授 → 例题/练习 → 总结/常见疑问/易错点等），不按讲义物理页序。
   - 每节给出 **pages**：该节应吸收的讲义页码数组（1 基）；讲义 1..N 的每一页至少要出现在一个章节中（一页同时支撑两节时可在两节各列一次，正文只展开最贴切处）。
   - 讲义多页连讲同一概念 → 归入同一节；同一概念被拆在多页/多段口述 → 合并，禁止一节一页地碎片化。
   - 若课堂含课程事务（作业/考试/协作规则等），单独成节放最前；若口述中反复强调某主题，给出对应的**教师强调**注释（可选字段 instructor_note）。
   - 可选收尾节（pages 可为空数组）：如 `常见疑问与解答（FAQ）`、`易错点总览（Common Pitfalls）`、`复现检查清单（Review Checklist）`。仅当对复习确有价值才添加，且内容必须只围绕本课真实讲过的点。
   - 课程类型为「{{course_type_label}}」：理论课侧重定义/定理/推导/直觉；实验课侧重步骤/环境/结果分析；习题课侧重题型/策略/易错；研讨课侧重观点/证据链。
3. 输出格式：**只输出一个 fenced ```json 代码块**（可先写一句“结构计划如下”，不要输出其它散文/大纲）。

JSON 结构：
```json
{
  "doc_title": "…",
  "sections": [
    {"heading": "…", "pages": [1, 2, 3], "instructor_note": "…(可省略)"},
    {"heading": "…", "pages": [4, 5, 6, 7]},
    {"heading": "…", "pages": []}
  ]
}
```
